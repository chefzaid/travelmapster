# Operations Runbook

This runbook covers the TravelMapster workload in the `apps` namespace. Shared PostgreSQL,
ingress, GitLab, Argo CD, Vault, logging and monitoring belong to bm-cluster; use its
[operations guide](https://github.com/chefzaid/bm-cluster/blob/main/docs/operations.md) for
platform-wide incidents. Commands use the platform kubeconfig.

## Runtime Surfaces

| Surface | Where |
|---|---|
| Application | <https://travelmapster.swirlit.dev>, also linked from the intranet homepage |
| Health | `/healthz` (process alive), `/readyz` (database reachable and not shutting down) |
| Metrics | Pod port 9464 `/metrics`, scraped by Prometheus; not exposed by the Service |
| Dashboards and logs | Grafana **Applications / travelmapster** and its Kibana counterpart, generated by the platform ([discovery](https://github.com/chefzaid/bm-cluster/blob/main/docs/observability.md#application-dashboards)) |
| CI, releases | GitLab project `swirlit/travelmapster` |
| Deployment | Argo CD Application `travelmapster` in `infra` |
| Code analysis | SonarQube project `swirlit:travelmapster` ([code quality](code-quality.md)) |

## First Checks

```bash
kubectl get application travelmapster -n infra        # Synced, Healthy
kubectl get deploy,pods,ingress -n apps -l app=travelmapster
kubectl get externalsecret -n apps | grep travelmapster  # all Ready=True
kubectl logs -n apps deploy/travelmapster --tail=50
```

Healthy means the Application is `Synced` and `Healthy`, the pod is ready with no restart
growth, and `/readyz` returns `{"status":"ready"}`.

## Logs And Metrics

Logs are JSON lines (pino) on stdout, one per request with method, URL, status and duration;
4xx log as `warn`, 5xx as `error`. Cookies, CSRF tokens and passwords are redacted.

| Metric | Meaning |
|---|---|
| `http_server_request_duration_seconds{method,route,status}` | Request latency and counts by route pattern |
| `travelmapster_auth_events_total{event,outcome}` | `register`, `login`, `password_change` and `account_delete` by outcome (`success`, `failure`, `conflict`) |
| Node.js defaults | Event loop lag, heap, GC, CPU and handles |

A rising `login` / `failure` rate points to credential stuffing; the auth rate limit answers
with 429.

## Common Incidents

| Symptom | Likely cause and action |
|---|---|
| Pod restarts with `Startup failed` | `SESSION_SECRET` missing or short, or migrations failed after ten attempts. Check `travelmapster-secret` exists and the database is reachable. |
| `/readyz` returns `database-unavailable` | Shared PostgreSQL is down, or the role password does not match the secret. Check the platform database, then the setup hook below. |
| `travelmapster-db-setup` fails | The admin credential ExternalSecret is not ready or PostgreSQL is unreachable. The hook reruns on every Argo CD sync. |
| Every user gets 429 | Client IPs are wrong, so all traffic shares one limit: `TRUST_PROXY` must match the pod network that Traefik runs in. |
| Place search returns 502 | Nominatim is unreachable, throttling, or the shared queue is longer than the timeout. Built-in country and city search keeps working; check pod egress to the internet. |
| A traveler is locked out by 429 | Wait for the window, or clear their counters: `DELETE FROM rate_limits WHERE key LIKE '%<client-ip>'` in the `travelmapster` database. |
| Import returns 413 | The file exceeds the JSON limit (3 MB) or the Traefik limit (4 MiB). |
| Everyone was logged out | `SESSION_SECRET` changed or the `sessions` table was cleared. |
| A manual `kubectl` change reverts | Argo CD self-heal; change the manifests in Git instead. |
| `02-deploy` times out | Inspect the Application's sync status and pod events (image pull uses `travelmapster-registry-auth`). |
| GitHub and GitLab differ | Run the "Sync GitHub and GitLab" workflow on GitHub; see [delivery](deployment.md#delivery-flow). |

## Rollback And Scaling

Roll back by pinning a previous image ([deployment](deployment.md#verification-and-rollback)).
The default profile runs one replica with 50m/192Mi requests and 500m/384Mi limits; use the
[HA profile](deployment.md#high-availability) for more.

## Backup And Recovery

The app keeps no volumes: all state is in the `travelmapster` database on the shared PostgreSQL.
The platform's daily host backup includes a `pg_dumpall` at `application-data/postgresql.sql.gz`
inside `/var/backups/bm-cluster/k3s/k3s-<timestamp>.tar.gz`
([platform backups](https://github.com/chefzaid/bm-cluster/blob/main/docs/operations.md#backups-and-recovery)).
Map data and assets are in the image.

To restore or drill, stream only this database's section into a scratch database, without
writing the all-databases dump to disk, then compare row counts with the source:

```bash
archive=/var/backups/bm-cluster/k3s/k3s-<timestamp>.tar.gz
sudo tar -xzOf "$archive" ./application-data/postgresql.sql.gz | gunzip \
  | awk '/^\\connect /{inside = ($0 ~ /dbname=.?travelmapster[" ]|^\\connect travelmapster$/)} inside && !/^\\connect /' \
  | psql -d restore_drill -v ON_ERROR_STOP=1
```

The scratch database needs a `travelmapster_user` role. Only the final database-level `GRANT`
fails when the target has another name. Drilled on 2026-09-27 against that day's archive: the
schema restored and matched production (no accounts existed yet). For a real recovery, restore
into `travelmapster` with the app scaled to zero, then scale it back up.

## Secret Rotation

Secrets live in Vault at `apps/travelmapster/runtime` (`database_password`, `session_secret`).
After changing one, refresh the Kubernetes Secret, rerun the setup hook so the database role
takes the new password, and restart the pods:

```bash
kubectl annotate externalsecret travelmapster-secret -n apps force-sync="$(date +%s)" --overwrite
kubectl patch application travelmapster -n infra --type merge -p '{"operation":{"sync":{}}}'
kubectl rollout restart deployment/travelmapster -n apps
```

Rotating `session_secret` signs every user out. The registry credential at
`apps/travelmapster/registry` is managed by onboarding.
